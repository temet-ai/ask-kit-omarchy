Report an Omarchy bug, suggest a feature, or send a fix upstream
1. Where it goes: a verified bug is a GitHub issue on omacom/omarchy (issues are for validated bugs, not support). A feature idea goes to the Suggestions category of its discussions. A support question or "is this a bug?" goes to the Omarchy Discord (https://omarchy.org/discord). Start with Discord when it is not clearly a bug in Omarchy itself.
2. Gather what the issue template asks for: CPU, GPU, Omarchy version (`scripts.run("version")`), steps to reproduce, what happened and what was expected, and diagnostics: `omarchy.text("debug", "--no-sudo", "--print")` prints the log (also written to /tmp/omarchy-debug.log). The interactive `omarchy debug` offers to upload it to logs.omarchy.org; leave that to the caller.
3. A screenshot or short recording of the problem is worth more than the description; see the skill `capture`. GitHub attachments are added by drag and drop in the web form, so give the caller the file path (`gh` cannot upload media).
4. A crash: the crash kit holds the coredump, backtrace and whether the fault is upstream.
5. Filing is the caller's: `gh issue create --repo omacom/omarchy --title ... --body ...` when `gh` is available. Include what happened, what was expected, steps, system details, the debug log link or file and the capture.
6. A fix: fork and clone (`gh repo fork omacom/omarchy --clone`), never develop against /usr/share/omarchy, follow the repository's AGENTS.md for style and commits, run its `./test/all` before pushing, open the PR with `gh pr create`, and add before/after captures for a visual fix.
