Build a desktop app for Omarchy the way Omarchy's own apps are built: C++ and Qt Quick, qmake, one binary, following the theme, installed as an Arch package
1. Decide the one job the app does and a short lowercase name (`tally`). The name is the binary, the package, the .desktop file, the icon and the Wayland app id. Reference apps: Omacut (video trimmer), Monologue (webcam recorder), Hype (Markdown presentations), Signed (PDF signing), all on GitHub under omacom or omacom-io.
2. Needs on the machine: `qmake6`, `make`, a C++ compiler, Qt base, declarative, multimedia, svg and wayland modules, and `ffmpeg`. If `qmake6` is missing, the caller installs them: `omarchy pkg add base-devel qt6-base qt6-declarative qt6-multimedia qt6-svg qt6-wayland ffmpeg`.
3. Scaffold (needs act): `omarchy.scaffold("<name>", { description, dir })`, then `scripts.run("app-check", { path })` for the conventions. The layout is `<name>.pro`, `bin/{build,test,install}`, flat `src/` (main.cpp, backend, theme, translator, Main.qml, resources.qrc, i18n/), `tests/`, `pkgbuild/{PKGBUILD,<name>.desktop,<name>.svg}`, README.md, LICENSE, .gitignore. No CMake, no committed build directories or generated files.
4. Split: C++ owns state, files, processes and anything that can fail, as a QObject with `Q_PROPERTY ... NOTIFY` and `Q_INVOKABLE`, given to QML by `setContextProperty("backend", &backend)`. QML owns layout and interaction: an `ApplicationWindow`, a few components, and every key binding as a `Shortcut` with `context: Qt.ApplicationShortcut`. Use `QGuiApplication`, and `app.setDesktopFileName("<name>")`. Material style, `Material.theme: Material.Dark`, accent from the theme, a dark window colour. Heavy media goes through `ffmpeg` and `ffprobe` with `QProcess`. Open and save dialogs go through xdg-desktop-portal over D-Bus (org.freedesktop.portal.FileChooser), never `QFileDialog`; Omacut's `src/portalfilepicker.{h,cpp}` behind an abstract `src/filepicker.h` is the pattern, and lets tests inject a fake picker.
5. Follow the theme live: read `accent` from `~/.local/state/omarchy/current/theme/colors.toml`, watch it (a theme switch replaces files and symlinks, so re-arm the watcher each change), fall back to `#FFD60A`. Corners: Hyprland's `decoration:rounding` is 0 by default; the Theme class asks `hyprctl` and exposes `theme.radius`; use it for panels, dialogs, buttons, `Material.roundedScale`, and cap small elements with `Math.min(4, theme.radius)`. Never change Omarchy's config.
6. Follow the language: wrap every visible string in `qsTr("Save")` (QML) or `tr("Save")` (C++), use `%1` with `.arg()`, and counted strings as `qsTr("%n clips", "", count)`. Catalogs are `src/i18n/<code>.json` (English text to translation, plural forms keyed by CLDR category) compiled in through resources.qrc. The Translator reads `~/.config/omarchy/language`, falls back `pt-BR` to `pt` to English, sets the default QLocale and layout direction. Write numbers and dates through `Qt.locale()`; keep content under the mirrored root for right-to-left languages. Translate the .desktop `Name` and `Comment` (`Name[da]=...`; regions use an underscore, `pt_BR`). Keep brand names, units and key names as they are.
7. Behaviour: place inserted things under the pointer when it is over the content, in the middle of what is visible otherwise, never at a fixed corner. Keyboard first: `?` lists shortcuts, `Q` quits (asks first when work is unsaved), Space is the main action, Ctrl+Z and Ctrl+Shift+Z undo and redo; the README lists them in a table. Never modify the user's originals; save atomically (write beside the target, then rename); ask before discarding work; say what is wrong in the window when a tool, device or permission is missing.
8. Agents can drive it: if the app makes or changes files, give it display-free commands as Hype does (`check`, `render`, `export`), each with `--json`, exit 0 or 1, errors on stderr, and `<name> skill install`. Set `QT_QPA_PLATFORM=offscreen` before `QGuiApplication` for them and keep the GUI behind `<name> open`.
9. The loop (the caller runs these; each takes time): `bin/build` and `build/<name>`; `bin/test` (builds the Qt Test binary and runs it offscreen; tests pass temp folders to anything that reads disk, the Theme takes the theme folder as an argument); look at it with `omarchy capture screenshot fullscreen save`; switch the language once (`omarchy language da`) and look again; for interaction work, a small harness that loads `qrc:/Main.qml` with `QT_QPA_PLATFORM=offscreen` and `QT_FORCE_STDERR_LOGGING=1`, sends events and saves `window->grabWindow()`; `bin/install` runs `makepkg -fsi`, installing the binary, the .desktop entry and the icon so the app shows in the launcher (Super + Space).
10. README opens with a screenshot of the app doing its job, from the offscreen harness with the default accent and made-up content (never the user's name, files or data). To ship: tag `v<version>`, make a GitHub release, then add the package to `omacom/omarchy-pkgs` under `pkgbuilds/<name>/` building from the release tarball, with `.omarchy/package.json` set to `"source": "local"`, `"auto_merge": true` and an `upstream.watch` on the repository. Only after that is it published can Omarchy install it by default (`install/omarchy-base.packages`, preinstall scripts, a migration).
11. Comments explain why, in full sentences. Commit messages are short and imperative. The templates come from Omacut and Monologue (MIT, David Heinemeier Hansson); keep that attribution in the LICENSE of an app that copies them (the scaffold writes it).
