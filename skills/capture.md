Screenshots, screen recordings, OCR and sharing with Omarchy's commands
1. Screenshot: `omarchy.run("capture", "screenshot", "fullscreen", "save")` saves straight to disk with no editor (needs act: it writes a file). Modes are `smart`, `region`, `windows`, `fullscreen`, `scroll`; a second argument `copy` or `save` sends it straight to the clipboard or disk. Region and window modes wait for a pointer selection, so only `fullscreen` is run from here. The default folder is ~/Pictures/Screenshots (`OMASNAP_SCREENSHOT_DIR` overrides it).
2. Recording (needs act): `omarchy.run("capture", "screenrecording", "--fullscreen")` starts (`omarchy screenrecord` is its alias), `omarchy.run("capture", "screenrecording", "--stop-recording")` stops and prints the saved path, `--status` reports. Always stop what you start, in the same ask. Without `--fullscreen` it opens a region picker, which this kit does not run. Flags: `--with-desktop-audio`, `--with-microphone-audio`, `--with-webcam`, `--resolution=<size>`. Without `--fullscreen` a region picker opens first. If it fails, rerun with `OMARCHY_SCREENRECORD_DEBUG=true` and read `$XDG_RUNTIME_DIR/omarchy-screenrecord.log`.
3. Text from the screen: `omarchy capture text` selects a region and puts the text on the clipboard; it needs a person to select, so this kit does not run it. To read what a window shows, the desktop kit does screenshots and OCR.
4. Sharing: `omarchy share clipboard|file <path...>|folder <path>` uses LocalSend; `omarchy tailscale send <machine> <file...>` uses Taildrop. `omarchy transcode <input> [format] [resolution]` shrinks a capture before sharing.
5. Find the commands for a related job with `scripts.run("commands", { find: "record" })`.
